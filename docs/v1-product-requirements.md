# 「写进照片」V1 产品需求文档

> 状态：已确认，作为 V1 的唯一需求基线。  
> 产品暂定名：**写进照片**。正式注册/上线前必须完成小程序名称与商标可用性核验。  
> 本文优先级高于早期讨论中的草案；需求变更需更新本文和关联技术方案。

## 1. 产品定位

「写进照片」是一款面向女性生活记录用户的微信小程序。用户上传一张真实生活照，系统自动添加白色手写文字、箭头、轮廓线和少量涂鸦，生成适合分享至朋友圈的手写 PLOG 图片。

### 核心用户

- 泛女性生活记录用户；
- 亲子妈妈与家庭记录用户；
- 宠物、旅行、日常生活内容用户；
- 有审美需求、但不愿意学习 Prompt 或手动排版的用户。

### 核心承诺

> 上传一张照片，自动把今天写进照片里。

## 2. V1 范围

### V1 做什么

1. 基于微信 OpenID 的静默身份识别（不强制索取昵称、头像等个人资料）。
2. 上传一张照片。
3. 用户选择场景：日常、旅行、亲子、宠物、其他。
4. 仅生成一种主风格：**白色手写 PLOG**。
5. 每次创作生成 1 张成图；用户可改文字、删元素、拖动位置。
6. 用户点击“换一版”时，重新调用模型并消耗 1 次创作额度。
7. 保存分享图，并在左下角放置一个不干扰画面的最小 `AI` 标识。
8. 展示最近作品。

### V1 不做什么

- 不上线甜酷涂鸦、旅行笔记等额外风格；它们作为后续付费增值内容储备。
- 不做广告位、激励视频、Banner 或插屏广告。
- 不做会员、支付、创作次数包；但数据模型必须支持未来的额度与订单扩展。
- 不开放用户自定义 Prompt。
- 不做批量处理、多照片拼贴、视频、社交社区或公开作品广场。

## 3. 为什么白色手写 PLOG 是引流款

白色手写 PLOG 是用户最容易理解、效果最稳定、与原帖验证内容最一致的第一款风格。它兼容亲子、旅行、宠物、吃喝和日常照片，同时保留真实照片的生活感。

甜酷涂鸦更适合年轻自拍/穿搭语境，风格偏好更强，不应分散 V1 的学习、提示词调校和审核成本。因此：

```text
免费引流款：白色手写 PLOG
后续付费增效款：甜酷涂鸦、旅行笔记、节日模板、批量处理、高清导出
```

## 4. 首页 UI（已确定）

采用已选的“干净蓝白 + 克制可爱”方向。

### 视觉原则

- 主色：柔和蓝紫；辅助色：奶油桃色、淡黄；背景为干净的暖白色。
- 以现代圆润无衬线中文为主，只有标题下划线、星星、爱心等使用少量手绘感点缀。
- 重点是照片，不做厚重手账纸张纹理，不堆叠卡片，不做幼态卡通。
- 亲子照片可用，但界面本身必须同时适合旅行、宠物和日常用户。

### 首页内容顺序

1. 顶部：`写进照片` Logo，右侧“作品”。
2. 标题：`一张照片，马上有故事`。
3. 大幅照片上传/预览区，预览区内有“更换照片”。
4. AI 场景识别摘要，例如：`识别到：亲子 · 户外 · 探险`。
5. 当前风格：`白色手写`；其他风格不在 V1 展示或操作。
6. 主按钮：`一键生成 PLOG`。
7. 说明：`生成后可改文字和位置`。
8. 小型“最近作品”入口。

## 5. 用户流程

```text
首页
  → 上传照片
  → 选择/修正场景
  → 一键生成
  → 生成等待页
  → 成图编辑页
  → 保存图片 / 分享朋友圈
  → 最近作品
```

### 编辑与保存页（已确定）

采用“成图优先”的第三版编辑页，不做复杂工具栏。页面结构固定为：

1. 顶部：返回、`你的 PLOG`、`重新生成`。
2. 主体：大尺寸成图预览，图片内始终展示 `写进照片 · AI 辅助创作` 落款。
3. 快捷编辑：`换句文案`、`少一点`、`移动文字`。
4. 唯一主按钮：`保存并分享`；保存后显示成功状态。
5. 提示：`已为你保留原照片`。
6. 次要操作：`做另一版`。

交互规则：

- `换句文案` 仅替换已生成的文字，不重绘照片；
- `少一点` 减少装饰和辅助注释；
- `移动文字` 调整文字在画布中的位置；
- `重新生成` 和 `做另一版` 触发新的 AI 创作并消耗一次创作额度；
- `保存并分享` 只保存当前成图，不应要求观看广告或额外操作。

### 创作额度与试用

- 新用户首次上传前阅读并确认照片处理说明后，获得 1 次免费 AI 创作。
- 一次创作 = 生成 1 张成图。
- 编辑已有成图不扣次数；“换一版”扣 1 次。
- 模型失败、审核拒绝、服务端异常必须自动返还次数。
- V1 不售卖次数包；体验结束后的付费入口先不开放，保留产品配置位。
- 服务端按 OpenID 执行额度校验、30 秒生成间隔和每日安全上限；不能只依赖前端按钮限制。
- 用户原图仅用于本次生成，生成结束后自动从云存储清理；生成图可在“我的作品”中由用户自行删除。

### 次数包预售界面（当前仅展示，不扣款）

当前小程序已展示次数包页，并已完成服务端订单创建、支付结果查询与额度发放代码；在商户 API 凭证、支付通知回调与验签全部配置和联调成功前，不得对外开放真实购买。服务端订单校验成功才写入额度：

| 商品 | 权益 | 标价 | 说明 |
| --- | ---: | ---: | --- |
| 首发尝鲜包 | 10 次 | ¥9.9 | 主推的低门槛首次购买包 |
| 日常记录包 | 30 次 | ¥24.9 | 面向有持续分享需求的用户 |

次数只在 AI 成功出图后扣减；保存、查看、删除作品均不扣次数。当前标准模型实测可变成本约 ¥0.19/张，付款前须保留平台支付手续费、云资源与失败重试缓冲。

支付接入实施中：订单由服务端创建，客户端只接收微信支付签名参数；用户支付后服务端需主动查询并核对交易状态、商户订单号与金额后才增加 `paidCredits`。正式发布前必须配置支付通知回调及验签，不能只信任客户端的“支付成功”回调。

## 6. 固定生成规则

### 不变量

1. 只添加白色手写 PLOG 覆盖层；不改变人物身份、脸、姿势、衣物、关键物件、背景和自然光。
2. 每张图默认 3–5 条短注释、1–3 个箭头、2–5 个小装饰；必须保留留白。
3. 文案仅使用画面可证实的信息，或用户明确选择/填写的信息。
4. 严禁臆测“第一次”“生日”“地点”“人物关系”等事实。
5. 所有文字必须清晰、中文准确、不可挡脸、手、主体动作或安全装备。
6. 导出图包含 `写进照片 · AI 辅助创作` 的设计化可见落款，并按技术方案保留所需文件标识信息。

### V1 固定 Prompt

```text
任务：基于用户提供的真实照片，只添加一层白色手写 PLOG 注释；不重绘、不改变原照片中的人物、五官、姿势、衣物、物体、背景、构图和自然光。

视觉风格：白色细线手绘，单线条完成，轻微自然抖动；像随手写下的日记，具有轻盈、温暖的 Instagram Story 与杂志手写笔记感。

先识别画面的场景、主体、动作、关键物件、留白与保护区域。注释分散地放在画面留白处，使用箭头、虚线与弧线指向真实存在的主体动作或物件；不得遮挡人物脸部、双手、主体动作与关键物件。保留足够留白，整体干净，不密集。

文字：使用中文自然手写感字体，短句、轻松、有情绪；仅使用画面可证实的信息或用户已确认的信息。不要编造第一次、地点、日期、人物关系或其他不可确认的事实。所有文字必须清晰、准确、可读。

装饰：只少量添加与场景相关的星星、爱心、叶子、蒸汽线、笑脸或路线虚线；不添加边框、拼贴、Logo、滤镜或无关物件。

输出：保持原图比例，生成一张适合朋友圈分享的成图。
```

### 动态变量

每张图只允许补充以下变量，不能改写上述固定规则：

```text
用户场景：{日常 | 旅行 | 亲子 | 宠物 | 其他}
识别主体：{主体}
真实动作：{动作}
关键物件：{物件}
氛围：{情绪}
可放文字区域：{留白位置}
禁止遮挡区域：{保护区域}
用户确认的补充信息：{用户输入/选择}
```

## 7. 数据与隐私

- 原图和中间生成文件：默认保存 24 小时后自动删除。
- 用户主动保存的作品历史：默认保留 30 天；用户可主动删除。
- 仅为本次生成使用上传照片；不得将用户照片用于训练、营销或其他用途，除非取得单独授权。
- 需在隐私政策中说明上传目的、第三方模型处理、保存期限、删除方式、投诉与反馈入口。
- 儿童照片属于高敏感内容，必须在上传、处理、历史保存和删除流程中优先保护。

## 8. 最低技术方案

### 技术选择

```text
前端：微信原生小程序 + 微信开发者工具
后端：腾讯 CloudBase（云函数、云数据库、云存储）
成图策略：一期采用**固定艺术总提示词 + 照片内容理解动态提示词 + AI 标注规划 + Canvas 字体合成**。艺术总提示词不可随意改动；动态提示词只描述图片中真实可见的场景、主体和动作。AI 负责产出注释内容、位置和箭头目标，真实中文手写字体由 Canvas 绘制，不能交给生图模型生成。

图像模型：腾讯混元图生图仅用于不含文字的高级特效或背景增强，不能作为基础 PLOG 的文字渲染器；Canvas 负责所有可读中文、品牌落款和最终导出。
内容安全：上传原图、导出成图均执行图片审核
```

### 选型原则

- V1 不接入 DeepSeek、千问等多个模型，避免成本、调试和合规材料变复杂。
- 优先使用单张公开价低、可提供小程序审核支持材料的国内图像服务；以实际图像效果、人物保持、中文可读性和资质材料为最终准则。
- 自动图像理解、结构化 Annotation Plan 和文案个性化分阶段增强；基础成图始终遵循“固定总提示词 + 动态图片理解提示词”的规则，Canvas 仅作为可编辑补充。
- 模型密钥只保存在云函数/云托管；小程序前端不得持有密钥。

### 任务状态

```text
queued → input_moderating → generating → output_moderating → completed | failed
```

创建任务时冻结创作次数；只有 `completed` 时确认消耗，其他失败状态自动返还。

## 9. V1 验证指标

V1 不是验证收入，而是验证产品价值。首轮种子用户测试需记录：

1. 上传后成功生成率；
2. 生成后导出率；
3. 7 天内第二次创作率；
4. 7 天内第三次创作率；
5. 生成失败率、重试率、平均耗时；
6. 用户主动编辑文字/位置的比例；
7. 用户对“愿意付费解锁更多风格/次数”的定性反馈。

## 10. V2 候选范围（不进入 V1）

- 甜酷涂鸦、旅行笔记等付费风格；
- 次数包、会员、微信支付；
- 流量主广告与激励视频；
- 多图拼贴、批量处理、相册故事；
- 图像理解 + Canvas 自动叠加，以进一步降低成本并提高编辑稳定性。
