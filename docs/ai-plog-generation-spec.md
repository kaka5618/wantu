# AI 手写 PLOG 图片生成规范

> V1 以 [「写进照片」V1 产品需求文档](v1-product-requirements.md) 为准；本文保留可复用的生成规则与未来扩展场景。

## 1. 目标

将用户的真实生活照片自动处理为适合朋友圈分享的手写 PLOG 图片：保留照片真实性，只叠加有叙事感的白色手写文字、箭头、轮廓线与少量涂鸦。

产品承诺：**上传一张照片，约 10 秒生成可直接分享的手写 PLOG 图。**

## 2. 核心原则

1. **原图优先**：不得改变人物身份、五官、姿势、衣物、装备、场景或真实光线；默认只增加覆盖层。
2. **先规划，后生成**：先识别图片并生成结构化的“标注方案”，再将方案填进固定提示词；不让模型每次自由改写整体风格。
3. **少而准确**：一张图默认 3–5 条文字标注、1–3 个箭头、2–5 个轻量装饰；留白优先于堆叠。
4. **不编造事实**：模型不得把无法从画面确认的事情写成事实，例如“第一次”“毕业了”“生日快乐”“在某城市”。这类内容只能由用户选择或补充。
5. **可编辑**：生成后用户必须能改文案、隐藏/删除标注、拖动位置并重新生成。
6. **隐私最小化**：分析只使用完成本次生成所需的信息；对人脸、儿童、证件、地址等区域提高保护优先级。
7. **文字与绘图分离**：图像模型只能生成白色轮廓线、箭头和小涂鸦，禁止生成任何汉字、字母、数字或拟似文字；所有用户可见中文必须由小程序 Canvas 用真实字体绘制并导出。任何模型即使偶尔能写对中文，也不能作为正式文字渲染器。

## 3. 生成流程

```text
用户上传照片
  → 图片安全检查
  → 视觉识别：场景、主体、动作、物件、情绪、留白、保护区域
  → 生成结构化标注方案（Annotation Plan）
  → 用户可选补充：场景标签 / 一句话心情 / 人物称呼
  → 固定基础 Prompt + 动态方案 Prompt（仅轮廓、箭头、涂鸦，无文字）
  → Canvas 以真实中文字体叠加标题与短句
  → 生成 2–3 个版本
  → 用户编辑文字与位置
  → 合规导出分享图
```

## 4. 图片识别输出：Annotation Plan

视觉模型必须输出 JSON；不要直接产出一段不可控的长提示词。

```json
{
  "scene_type": "child_outdoor_adventure",
  "primary_subjects": ["戴蓝黄头盔的孩子"],
  "key_actions": ["站在绳网桥上", "手握安全绳"],
  "key_objects": ["头盔", "安全带", "绳网桥", "树林"],
  "mood": ["阳光", "勇敢", "探索"],
  "safe_text_areas": ["左上树叶留白", "左下边角", "右下边角"],
  "protected_areas": ["人物脸部", "双手", "安全装备扣具", "主体轮廓"],
  "caption_candidates": [
    "今天的小小探险家",
    "勇敢闯进森林里",
    "抓紧啦，慢慢走"
  ],
  "claims_requiring_user_confirmation": ["第一次走绳网桥"]
}
```

### 必填字段

| 字段 | 用途 |
| --- | --- |
| `scene_type` | 选择场景模板与文案语气。 |
| `primary_subjects`、`key_actions`、`key_objects` | 决定描边对象、箭头目标与文字主题。 |
| `mood` | 决定措辞，例如治愈、热闹、松弛、勇敢。 |
| `safe_text_areas` | 文字与装饰的候选位置。 |
| `protected_areas` | 绝不覆盖的关键区域。 |
| `caption_candidates` | 仅使用画面可支持的中性短句。 |
| `claims_requiring_user_confirmation` | 不确定事实，必须在 UI 中让用户选择或填写。 |

## 5. 场景模板

模板只改变“叙事对象、文案词库、装饰”，不改变基础视觉规则。

| 场景 | 关注元素 | 安全文案语气 | 推荐装饰 |
| --- | --- | --- | --- |
| 美食/咖啡 | 食物、饮品、餐桌、光线 | 口感、温度、满足感 | 蒸汽线、叉子、小爱心 |
| 旅行/风景 | 地标、天空、道路、人物 | 到达、风、散步、治愈 | 路线虚线、太阳、云朵 |
| 日常自拍/穿搭 | 人物、服装、镜子、光线 | 今日状态、颜色、心情 | 星星、蝴蝶结、小花 |
| 亲子/户外 | 人物、动作、装备、自然环境 | 探索、陪伴、勇敢、放电 | 叶子、路线、小旗子、星星 |
| 宠物 | 宠物动作、表情、玩具 | 可爱、撒娇、陪伴 | 爪印、爱心、对话泡泡 |
| 家居/日常记录 | 桌面、植物、房间、物品 | 松弛、整理、日常小确幸 | 小格子、勾选符号、花朵 |

## 6. 固定基础 Prompt

每次生成均保留以下约束；动态变量由 Annotation Plan 替换。

```text
任务：基于用户提供的真实照片，只添加一层白色手写 PLOG 注释；不重绘、不改变原照片中的人物、五官、姿势、衣物、物体、背景、构图和自然光。

视觉风格：白色细线手绘，单线条完成，轻微自然抖动；像随手写下的日记，具有 Instagram Story 与杂志手写笔记的轻盈感。

排版：注释分散地放在 {safe_text_areas}，使用箭头、虚线与弧线指向 {key_actions} 或 {key_objects}；不得遮挡 {protected_areas}。保留足够留白，整体干净，不密集。

文字：本阶段**不得生成任何文字、汉字、字母、数字、标题、签名或拟似文字**。中文自然手写感标题和短句由 Canvas 按 `caption_candidates` 以真实字体绘制；只使用画面可证实的信息或用户已确认的信息。所有文字必须清晰、准确、可读。

装饰：仅少量使用与 {scene_type} 匹配的 {decorations}。不添加边框、拼贴、Logo、滤镜或无关物件。

输出：保持原图比例；生成 3–5 条注释、1–3 个箭头、2–5 个小装饰。
```

## 7. 动态 Prompt 组装规则

```text
场景：{scene_type}
主要主体：{primary_subjects}
画面动作：{key_actions}
关键物件：{key_objects}
氛围：{mood}
文字安全区域：{safe_text_areas}
绝对不可遮挡区域：{protected_areas}
候选文案：{selected_caption_candidates}
用户确认的补充事实：{user_confirmed_facts}
```

### 儿童户外示例

```text
场景：亲子户外挑战
主要主体：戴安全头盔的孩子
画面动作：站在绳网桥上、手握安全绳
关键物件：头盔、安全带、绳网桥、树林
氛围：阳光、勇敢、探索
文字安全区域：左上树叶留白、左下边角、右下边角
绝对不可遮挡区域：孩子脸部、双手、安全装备扣具、绳网桥主体
候选文案：今天的小小探险家；抓紧啦，慢慢走；森林探险日；今天也超勇敢
```

## 8. UI 交互要求

1. 上传后默认自动识别并生成 2–3 个版本。
2. 在生成前或生成后提供轻量选项：`旅行`、`吃喝`、`日常`、`亲子`、`宠物`、`其他`。
3. 对“第一次、纪念日、地点、姓名、关系”等不确定信息，以可选标签或输入框让用户确认。
4. 每条文字可编辑、删除、替换；每个元素可拖拽；支持“少一点”“更可爱”“更简洁”的再生成指令。
5. 重新生成必须保留原图和用户已确认的事实，不能随机更改真实人物/场景。

## 9. 质量验收清单

- [ ] 人物脸部、身份、姿势、衣物、装备未被改变。
- [ ] 所有文案有画面依据或已被用户确认。
- [ ] 所有中文无错字、无乱码、可读。
- [ ] 文字不压住脸、手、主体动作或关键物件。
- [ ] 元素数量适中，图片仍有呼吸感。
- [ ] 箭头指向正确对象，描边没有把所有物体机械勾满。
- [ ] 场景风格与用户选项一致。
- [ ] 导出尺寸与分享场景匹配，并按合规方案保留所需生成内容标识。

## 10. 不做的事

- 不根据照片臆测“第一次”“生日”“地点”“亲属关系”等事实。
- 不让模型重绘孩子、人脸、食物或场景来换取风格化效果。
- 不覆盖或隐匿生成内容所需标识；分享图的视觉标识应作为版式的一部分设计。
- 不把用户照片用于本次生成以外的用途，除非用户另行授权。
